# สถานะหลังแก้ครบตามผลตรวจ

20 ตุลาคม 2569 — โค้ดใน Desktop/probiotic-shop

## เพิ่มรูปสินค้า

Admin → จัดการสินค้า → เพิ่มสินค้า/แก้ไข → **อัปโหลดรูปสินค้า JPG หรือ PNG ไม่เกิน 5 MB** → เลือกไฟล์ → ตรวจตัวอย่าง → **บันทึกสินค้า**

ระบบเก็บไฟล์ใน `backend/image/pdimages` และเชื่อม path กับสินค้าเอง ไม่ต้องคัดลอกไฟล์หรือพิมพ์ URL รูปเดิมคงอยู่เมื่อแก้ข้อความ มีปุ่มนำรูปออกจากสินค้า (ไม่ลบไฟล์โดยอัตโนมัติ เพื่อไม่กระทบรายการอื่น)

```text
backend/image/
  pdimages/  รูปสินค้า JPG/PNG เปิดอ่านผ่าน URL รูปได้
  slip/      หลักฐาน JPG/PNG/PDF ต้องตรวจสิทธิ์
  receipt/   ใบรับแจ้ง/ใบเสร็จ PDF ต้องตรวจสิทธิ์
```

ภาพสำรองเดิมเป็น CSS จึงไม่มีไฟล์ JPG/PNG ให้ค้นหา หากมีไฟล์เก่าใน uploads/products ให้รัน `npm.cmd run media:migrate` เพื่อคัดลอกมา pdimages โดยเก็บต้นฉบับและไม่เขียนทับปลายทาง รองรับ path เก่าและ URL เดิม พร้อม fallback เมื่อรูปเสีย

## สิ่งที่แก้ครบ

| ปัญหา/ข้อเสนอ | สิ่งที่แก้แล้ว |
| --- | --- |
| ชุดติดตั้งหาย | คืน schema.sql, catalog.sql, probiotic_shop_complete.sql และ .env.example พร้อมโครงสร้างล่าสุด SQL ติดตั้งไม่มีบัญชีส่วนตัว |
| ติดตั้ง/รันซ้ำ | ทดสอบ import บน DB ว่าง, migration สองครั้ง, seed สองครั้งไม่ซ้ำ Server ตรวจ migration ก่อนรับคำขอ |
| สต็อกถูกเขียนทับ | products.version เพิ่มทุกครั้งที่แก้/ซ่อน/จอง/คืนสต็อก PUT ตรวจ expected_version แบบ atomic ฟอร์มเก่าตอบ 409 โดยไม่เขียนทับ |
| ราคาตะกร้าต่างจากออร์เดอร์ | โหลดราคา/สต็อกล่าสุดและให้ยืนยันอีกครั้งเมื่อเปลี่ยน Server ตรวจ expected_unit_price และ expected_total ภายใน transaction |
| สินค้าไม่พร้อมขายในตะกร้า | แจ้งให้ปรับจำนวนหรือนำออก ไม่รับออร์เดอร์ที่จำนวนเกินหรือปิดขาย |
| Retry key กับข้อมูลอื่น | request_hash ตรวจ payload; key เดิม/ข้อมูลเดิมไม่สร้างซ้ำ ข้อมูลเปลี่ยนตอบ 409 |
| Username ชน email | Username ใหม่ใช้ A–Z/a–z/0–9/._- 3–50 ตัว ห้าม @ Login ที่มี @ ค้นหา email โดยตรง บัญชีเก่าที่ชื่อเหมือนอีเมลใช้ email ที่ลงทะเบียนเข้าสู่ระบบได้ |
| ออร์เดอร์กันสต็อกค้าง | expires_at ค่าเริ่มต้น 24 ชั่วโมง ปรับ ORDER_PAYMENT_HOURS 1–168 ได้ ตรวจทุกนาทีและก่อนอ่าน/ชำระ ล็อกและคืนครั้งเดียว pending_review ไม่หมดอายุระหว่างรอตรวจ |
| ไม่มีจัดส่ง | Admin บันทึกขนส่ง/เลขพัสดุหลังอนุมัติชำระ เปลี่ยน shipped → completed ลูกค้าเห็นสถานะ/เวลา/เลขพัสดุและยังโหลดใบเสร็จได้ |
| รายละเอียดสินค้า | เพิ่มขนาดบรรจุ วิธีใช้ การเก็บรักษา ข้อควรระวัง ให้กรอกตามสินค้าจริง ไม่เดาข้อมูลบนฉลาก |
| รูปหายเมื่อแก้ข้อความ | อัปโหลดจากเครื่อง ตรวจ JPG/PNG ที่อ่านข้อมูลภาพได้ สูงสุด 5 MB/25 ล้านพิกเซล จำกัด Admin เก็บรูปเดิมได้และแสดง fallback หากหาไฟล์ไม่พบ |
| รายการโหลดทั้งหมด | pagination สำหรับสินค้า Admin/Customer, orders และ payments; page_size สูงสุด 100 |
| ฐานข้อมูลพึ่งค่า default | InnoDB/utf8mb4 ชัดเจน เพิ่ม CHECK ราคา/สต็อก/จำนวน/ยอด และ index ตรวจหมดอายุ |
| Vue ใช้ tag rc ที่เปลี่ยนได้ | ตรึง Vue และแพ็กเกจ Vue เป็นเวอร์ชันทดสอบ 3.6.0-rc.10 และปรับ lockfile |
| SMTP ยังไม่มีหลักฐานครบ | ทดสอบ Nodemailer ส่งผ่าน SMTP loopback แล้ว reset จาก token จริง ตรวจ reuse/รหัสเก่า/JWT เก่า; provider verify ผ่านโดยไม่ส่งอีเมลภายนอก |
| เอกสารไม่ตรงหลังแก้ | อัปเดต Mapping, Dictionary ครบ 8 ตาราง, ER Diagram, HTML/PDF, README และ payload Postman |

ฟีเจอร์รอบก่อนยังคงอยู่: Dashboard export CSV/JSON, เงื่อนไข password ครบพร้อม checklist/ยืนยัน, ชมพูพาสเทล–ม่วง, โหมดสว่าง/มืด, ตัวอักษรใหญ่, ปุ่ม/ช่องกรอกใหญ่ และการตรวจสิทธิ์เอกสารส่วนตัว
