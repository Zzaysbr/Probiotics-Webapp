# สิ่งที่เพิ่มตามข้อเสนอแนะการนำเสนอ

## การใช้งานที่เพิ่ม

### 1. Export Dashboard

1. เข้าสู่ระบบ Admin → Dashboard
2. เลือกตั้งแต่วันที่/ถึงวันที่ แล้วกด **แสดงผล**
3. เลือก **CSV (เปิดใน Excel)** หรือ **JSON (ข้อมูลทั้งหมด)**
4. กด **ดาวน์โหลดข้อมูล** ไฟล์อยู่ใน Downloads ตามการตั้งค่าเบราว์เซอร์

รายงานรวมยอดขายสรุป รายวัน สินค้าขายดี และสต็อกปัจจุบัน ชื่อไฟล์แสดงวันที่ของข้อมูลที่โหลดสำเร็จ หากเปลี่ยนตัวกรองโดยยังไม่กดแสดงผล จะ export ชุดข้อมูลที่แสดงอยู่ ไม่ติดวันที่ที่ยังไม่ได้ค้นหา รายการรอตรวจทั้งหมดและสต็อกเป็นค่าปัจจุบัน ไม่ใช่ค่าภายในช่วงวันยอดขาย CSV ระบุขอบเขตนี้แยกไว้

CSV รองรับภาษาไทยด้วย UTF-8 BOM และ escape comma/quote/newline รวมถึงชื่อสินค้าที่อาจถูกโปรแกรม spreadsheet ตีความเป็นสูตร JSON เก็บโครงสร้างข้อมูลครบและเวลา export เป็น UTC ISO พร้อมระบุเขตเวลารายงาน Asia/Bangkok ไม่มีข้อมูลส่วนตัวผู้ซื้อในชุดข้อมูล Dashboard

### 2. รหัสผ่านใหม่

หน้าสมัครและ reset แสดง checklist เดียวกันซึ่งตรงกับกติกา backend:

- อย่างน้อย 8 ตัวอักษร
- ภาษาอังกฤษตัวใหญ่ A–Z อย่างน้อย 1 ตัว
- ภาษาอังกฤษตัวเล็ก a–z อย่างน้อย 1 ตัว
- ตัวเลข 0–9 อย่างน้อย 1 ตัว
- สัญลักษณ์พิเศษที่รองรับอย่างน้อย 1 ตัว พร้อมแสดงรายการครบ
- ไม่เกิน 72 ไบต์ตามข้อจำกัดการรับรหัสผ่านของ backend; ภาษาอังกฤษ/ตัวเลข/สัญลักษณ์ที่แสดงใช้ตัวละ 1 ไบต์

เมื่อพิมพ์จะแสดงเครื่องหมายและข้อความที่ screen reader อ่านได้ ไม่ใช้เพียงสีบอกสถานะ มีช่องยืนยันรหัสผ่านใหม่เพื่อป้องกันพิมพ์ผิด และปุ่ม “แสดง/ซ่อน” ที่มีทั้งข้อความกับไอคอน เงื่อนไขเว้นวรรคและอักษรไทยอธิบายไว้ชัดเจน หากมาจากลิงก์อีเมล ระบบรับ token จาก URL โดยไม่ให้ผู้ใช้คัดลอกเอง

### 3. โฟลเดอร์เอกสาร

```text
backend/
  image/
    slip/       สลิป JPG, PNG หรือ PDF
    receipt/    ใบรับแจ้งชำระและใบเสร็จ PDF
```

- สลิปอัปโหลดใหม่บันทึกใน image/slip ใช้ชื่อสุ่มเดิม และบันทึกชื่อไฟล์ใน payments
- PDF บันทึกเมื่อดาวน์โหลดครั้งแรก และใช้ไฟล์เดิมในการดาวน์โหลดครั้งต่อไป ชื่อไฟล์ภายในผูก order ID, payment ID และสถานะ pending/approved จึงไม่สับสนระหว่างใบรับแจ้งกับใบเสร็จจริง
- ตรวจสิทธิ์เจ้าของออร์เดอร์หรือ Admin ผ่าน API ก่อนอ่านไฟล์ทุกครั้ง ไม่มี static route เปิดโฟลเดอร์ image
- สลิปเดิม 3 ไฟล์ถูกคัดลอกจาก storage/slips มา image/slip โดยเก็บต้นฉบับไว้ ไม่เขียนทับไฟล์ปลายทางที่มีอยู่แล้ว และยังมี fallback อ่านตำแหน่งเดิมได้
- `npm.cmd run media:migrate` เรียกซ้ำได้ สำรองทั้งฐานข้อมูลและ backend/image ไปพร้อมกัน ไฟล์จริงไม่เข้า Git มีเฉพาะ .gitkeep
- ไฟล์จาก automated tests อยู่ใต้ backend/tmp/media-test-<process ID> แยกจากเอกสารร้าน

### 4. โหมดสีและการอ่าน

- ใช้ชมพูพาสเทลและม่วงเป็นพื้น/องค์ประกอบประกอบกับข้อความสีเข้มที่อ่านชัด
- โหมดมืดใช้พื้นม่วงเข้มกับข้อความสีอ่อน และปรับฟอร์ม ตาราง แถบเมนู หน้า Home/Contact/Profile และหน้าซื้อขายให้สอดคล้องกัน
- ปุ่มเปลี่ยนโหมดและตัวอักษรใหญ่อยู่ด้านบนทุกหน้า ใช้ได้โดยไม่ต้องล็อกอินและจำค่าบนอุปกรณ์เดิม ค่าเริ่มต้นของโหมดสีอิงระบบ
- ข้อความหลักเริ่มที่ 17px; ตัวอักษรใหญ่เพิ่มฐานเป็น 20px ปุ่มหลัก/ช่องกรอกอย่างน้อย 48px และปุ่มควบคุมอย่างน้อย 44px
- เพิ่มลิงก์ข้ามไปเนื้อหาหลักเมื่อใช้คีย์บอร์ด, focus ที่เห็นชัด, สถานะ aria-pressed ของตัวเลือก, ภาษาไทยบนฟอร์มบัญชี และรองรับ reduced motion
- เมื่อเปิดตัวอักษรใหญ่ ฟอร์มตัวกรองเรียงเป็นแนวตั้งบนจอที่แคบลง ตารางกว้างยังเลื่อนแนวนอนภายในกรอบได้
